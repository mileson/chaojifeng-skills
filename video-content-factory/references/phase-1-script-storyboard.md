# 阶段1：口播稿与分镜稿生产

本文件规定 **video-content-factory** 阶段1 的完整执行流程：选题 → 调研 → 策略简报 → 口播稿 → 分镜稿，并重点说明如何在分镜表中按句绑定特效库 ID。

阶段1 的产物是**可直接对照录制**的稿件。用户录完后，直接进入阶段2 做自动剪辑、特效合成与发布包输出。

---

## 1. 目标与边界

| 范围 | 说明 |
|------|------|
| **做什么** | 产出 `topic-brief.md` → `research.md` → `BRIEF.md` → `SCRIPT.md` → `STORYBOARD.md` |
| **不做什么** | 不生成真实素材、不渲染特效、不剪辑视频、不输出发布包 |
| **核心交付** | `SCRIPT.md`（口播稿）+ `STORYBOARD.md`（分镜稿），其中分镜表按句预绑定特效模式 ID |
| **特效库** | 统一使用本 Skill 内 `assets/effects_library/`，四件套规范见 `references/effects-library-spec.md` |

---

## 2. 开工前置

每次新建项目必须按顺序执行：

1. **读取长期记忆与品牌配置**
   - `data/memory.md`：复用历史偏好、踩坑记录、已验证特效。
   - `data/brand-profile.yaml`：复用署名边界、平台偏好、默认画幅。

2. **初始化工程目录**

   ```bash
   python3 scripts/init_project.py ./<项目目录> --topic "<选题名>"
   ```

   该命令会在项目目录生成：

   ```text
   <项目目录>/
   ├── topic-brief.md
   ├── research.md
   ├── BRIEF.md
   ├── SCRIPT.md           # 基于 templates/SCRIPT.template.md
   ├── STORYBOARD.md       # 基于 templates/STORYBOARD.template.md
   ├── assets/
   ├── aroll/
   └── publish/
   ```

3. **若用户已提供工程目录**，则直接在该目录读写上述文件，不再重复初始化。

## 3. 流程总览

| 阶段 | 产物文件 | 核心动作 | 质量门禁 |
|------|----------|----------|----------|
| Stage 0 选题立项 | `topic-brief.md` | 一句话选题、平台、受众 | 能用一句话说清视频价值 |
| Stage 1 调研 | `research.md` | 论点、数据、竞品、素材候选 | 每条核心论点带来源 |
| Stage 2 策略简报 | `BRIEF.md` | 锁定 9 项关键决策 | 全部锁定后方可写稿 |
| Stage 3 口播稿 | `SCRIPT.md` | 短句分行、口语化、估算时长 | 需可朗读、钩子在前 15s |
| Stage 4 分镜稿 | `STORYBOARD.md` | 按句拆分、A/B-Roll 判定、绑定特效 ID | 覆盖率与连续性自检通过 |

## 4. 各阶段详细规则

### 4.1 Stage 0：选题立项（`topic-brief.md`）

用一句话把选题说死：

> 给 **【受众】** 看的关于 **【主题】** 的 **【类型】** 视频，看完记住 **【一件事】**。

`topic-brief.md` 至少包含：

- **选题名**：项目目录名尽量与它一致。
- **核心主张**：一句话结论。
- **目标平台**：B 站 / 视频号 / YouTube / 抖音等，影响画幅与节奏。
- **发布时机**：如有特殊节点需说明。
- **是否继续**：写不出来就回炉，不要硬进 Stage 1。

### 4.2 Stage 1：调研（`research.md`）

调研产物必须包括：

1. **核心论点**：每条论点后面注明来源或证据类型。
2. **可引用数据**：精确数字、对比值、出处链接。
3. **竞品 / 对标**：同选题别人怎么讲，我们如何差异化。
4. **素材候选清单**：哪些画面可以屏录、截图、AI 生成或实拍。
5. **可用特效联想**：初步判断哪些叙事节点可能需要特效（只在备注里提，不绑定 ID）。

> 数据/证据类镜头**必须**用真实屏录或真实截图，禁止用 AI 生成画面冒充。

### 4.3 Stage 2：策略简报（`BRIEF.md`）

`BRIEF.md` 锁定以下 9 项后才能进入 Stage 3：

1. **Message**：观众看完只记住的一句话。
2. **叙事弧**：Problem→Solution / Reveal / Demonstration / Vibe / Comparison 等，附一句话形状。
3. **受众**：谁 + 在哪看 + 他们已有的认知。
4. **类型**：产品发布 / 教程 / 观点 / Build in Public / 测评。
5. **时长**：X 分钟，约 Y 字逐字稿（按 4 字/秒估算）。
6. **钩子策略**：前 15 秒方案，必须是大胆断言、反差或具体数字。
7. **风格节奏**：快剪 / 沉稳 / 教程感 / 访谈感等。
8. **口播密度**：全程口播 / 口播+演示交替 / 画面为主。
9. **平台画幅**：横屏 1920×1080 / 竖屏 1080×1920，注明主平台。
10. **单句测试答案**：这条视频和同选题视频的差异点。

用户已明确的项直接复用；缺失项才询问。用户说"你定"时，AI 自主决策并在对应项后标注 `决策人: AI`。

### 4.4 Stage 3：口播稿（`SCRIPT.md`）

基于 `BRIEF.md` 写出口播稿，规则如下：

- **短句分行**：每行一句，≤20 字/行。
- **口语化**：使用"就是、其实、那、你会发现"等口语连接词。
- **时长估算**：约 4 字/秒。总字数 ÷ 4 ≈ 预估秒数。
- **编号清晰**：每句前标注 `（第 N 句）`，方便分镜表一一对应。
- **拍摄提示不念出**：用 `> 拍摄提示：` 块标注动作、眼神、道具，不计入口播时长。
- **钩子三秒定律**：前 15 秒内必须有钩子，禁止"大家好今天我们来聊聊"。
- **CTA 单一**：结尾只留一个主动作（关注 / 点赞 / 评论 / 下载 四选一）。

`SCRIPT.md` 结构见 `templates/SCRIPT.template.md`。

#### 口播稿质量门禁

- [ ] 每句朗读时不拗口。
- [ ] 前 15 秒出现钩子或反差断言。
- [ ] 无超过 30 字的冗长句。
- [ ] CTA 只有一个主动作。
- [ ] 总字数与 `BRIEF.md` 中的时长目标误差 ≤20%。

### 4.5 Stage 4：分镜稿（`STORYBOARD.md`）

分镜稿是阶段1 的**核心产物**，也是阶段2 的输入事实源。

#### 4.5.1 分镜表拆分原则

- **按句拆分**：把 `SCRIPT.md` 的每一句拆成一行。
- **一句一行**：不要把两句合并成一行，也不要把一句拆成多镜（除非句子过长或节奏需要）。
- **A-ROLL / B-ROLL 判定**：
  - **A-ROLL**：观众看主讲人口播，无画面特效。
  - **B-ROLL**：画面上需要叠加特效、素材或切换画面。
- **段落归组**：用"开头钩子 / 痛点共鸣 / 核心论点 / 证据演示 / 算账对比 / 金句收口 / CTA"等段落名给镜号分组。

#### 4.5.2 分镜表字段

分镜表使用以下列：

| 列名 | 必填 | 说明 |
|------|------|------|
| 镜号 | 是 | 从 1 开始连续编号 |
| 段落 | 是 | 该镜所属叙事段落 |
| 台词 | 是 | 来自 `SCRIPT.md` 的对应句 |
| 类别 | 是 | `A-ROLL` 或 `B-ROLL` |
| 特效模式 | B-ROLL 必填 | `registry.json` 中的特效 ID；A-ROLL 填 `-` |
| 画面描述 | 是 | 镜头语言、构图、关键视觉元素 |
| 素材策略 | B-ROLL 必填 | 屏录 / AI图 / 实拍 / 特效库 / 暂无 |
| 预估时长 | 是 | 按口播速度估算，B-ROLL 通常 3~8s |
| 真实时间戳 | 阶段2 回填 | 剪辑后填入成片时间 |
| 状态 | 是 | `待生成` / `已录制` / `已合成` 等 |
| 本镜目的 | 是 | 这一镜观众该记住什么 |

#### 4.5.3 分镜稿质量门禁

- [ ] **B-Roll 覆盖率 ≥40%**：观众不能一直看大头。
- [ ] **最长 A-Roll 连续段 ≤20s**：超过 20s 必须有画面变化或切 B-Roll。
- [ ] **B-Roll 连续不超过 30s**：避免失去人感。
- [ ] **Pattern Interrupt 最大间隔 ≤60~90s**：定期出现视觉节奏变化。
- [ ] **钩子镜头专门设计**：前 15 秒不能只是人物正面中景。
- [ ] **每镜目的非空**：每行必须写清"观众该记住什么"。
- [ ] **CTA 有画面事件**：不要只说"记得三连"，要配合 `follow-pill` 等特效。
- [ ] **证据类镜头用真素材**：数据/对比/算账画面必须屏录或真实截图。
- [ ] **特效模式绑定率 100%**：B-ROLL 行必须填特效 ID，不能空着。

## 5. 特效库绑定规则（重点）

### 5.1 绑定前必须做的事

1. **打开特效库管理界面**：用浏览器直接打开 `assets/effects_library/index.html`，按分类浏览、搜索、复制特效 ID。
2. **读注册表**：`assets/effects_library/registry.json` 是特效的唯一事实源，脚本与 Agent 都从这里查。
3. **读目录说明**：`assets/effects_library/catalog.md` 说明每个特效的适用场景、结构要点、动画要点。
4. **读代码范式**：确定使用某特效后，再读 `assets/effects_library/snippets/<id>.html` 了解可替换字段。

### 5.2 绑定规则

- **A-ROLL 行**：`特效模式` 列统一填 `-`，表示不需要特效。
- **B-ROLL 行**：`特效模式` 列必须填写 `registry.json` 中已存在的特效 ID。
- **ID 格式**：小写字母 + 连字符，例如 `stamp-hook`、`countup-price`、`follow-pill`。
- **禁止绑定未注册 snippet**：未进 `registry.json` 的 snippet 视为未入库，不能直接使用。
- **无匹配时的处理**：若现有特效库没有合适模式，填 `NEW: <一句话设想>`，例如：

  ```text
  NEW: 一个从屏幕底部弹出的「限时免费」胶囊条，带脉冲呼吸
  ```

  后续在阶段2 设计并验证通过后，按 `references/effects-library-spec.md` 完成四件套入库。

### 5.3 按叙事意图选特效类别

| 叙事意图 | 推荐特效类别 | 本 Skill 已有示例 | 说明 |
|----------|--------------|-------------------|------|
| 开场钩子 / 反差 | `beat` | `stamp-hook` | 3~5s 制造强烈视觉反差 |
| 价格 / 数据 / 算账 | `beat` | `countup-price` | 数字滚动印章，突出结论 |
| 关注 / 订阅 / CTA | `beat` | `follow-pill` | 片尾药丸按钮引导 |
| 章节切换 | `transition` | — | 每 20s 左右一次，避免滥用 |
| 常驻 HUD / 进度 | `skeleton` | — | 教程类视频提供持续锚点 |
| 产品演示 / 画中画 | `container` / `product` | — | 承载 App 界面、仪表盘 |
| 片尾作者信息 | `outro` | — | 不透明拼接段，接在成片后 |

### 5.4 绑定示例

假设 `SCRIPT.md` 有如下几句：

```text
- （第1句）Cursor 旧版按次计费，一次调用只要两毛钱。
- （第2句）但很多人一听到「按次」就慌了。
- （第3句）来算一笔账：20 美元一个月，按 500 次摊，每次才 0.2 元。
- （第4句）如果你关注我，后面还有更多省钱玩法。
```

对应 `STORYBOARD.md` 的特效绑定：

| 镜号 | 段落 | 台词 | 类别 | 特效模式 | 画面描述 | 素材策略 | 预估时长 | 本镜目的 |
|------|------|------|------|----------|----------|----------|----------|----------|
| 1 | 钩子 | 第1句 | B-ROLL | `stamp-hook` | 两枚旋转印章 + 删除线，呈现「贵？→ ¥0.2」反差 | 特效库 | 5s | 用视觉反差把价格优势烙进脑子 |
| 2 | 痛点 | 第2句 | A-ROLL | `-` | 人物近景，表情略带惊讶 | 口播实拍 | 5s | 让观众点头「我也是」 |
| 3 | 算账 | 第3句 | B-ROLL | `countup-price` | 数字滚动到 0.2，配价格印章 | 屏录+特效库 | 7s | 把抽象价格摊成具体数字 |
| 4 | CTA | 第4句 | B-ROLL | `follow-pill` | 黑色药丸按钮 + 副标语淡出 | 特效库 | 5s | 只留「关注」一个动作 |

### 5.5 参数化说明

- 分镜表**只绑定特效 ID**，不需要把文案/数字写进 snippet。
- 具体文案、数值、配色在阶段2 根据当期视频重写，写在 snippet 顶部的可替换字段注释处。
- 如需强调某个参数（例如"数字要滚到 0.2"），可在 `画面描述` 或 `本镜目的` 中备注。

## 6. 时间轴约定

- **预估时长**：口播稿按 4 字/秒估算；B-ROLL 特效节拍通常 3~8s，不要超过该句口播时长 +0.5s。
- **呼吸留白**：每个 B-ROLL 节拍前后至少留 0.15s 进出场的呼吸空间。
- **真实时间戳**：阶段2 剪辑完成后，根据 ASR 词级时间戳回填到 `真实时间戳` 列，成为阶段2 节拍表的 ground truth。
- **偏差处理**：若真实时长与预估偏差 >15%，优先调分镜/特效节奏，而不是硬改音频。

---

## 7. 反模式清单

阶段4 自检时必须逐条检查：

- ❌ B-Roll 覆盖率 < 40%。
- ❌ A-Roll 连续超过 20s 没有任何画面变化。
- ❌ B-Roll 连续超过 30s 不回 A-Roll。
- ❌ 提示词 / 画面描述与台词语义脱节。
- ❌ 数据 / 对比 / 证据类台词配 AI 生成画面。
- ❌ 钩子镜头（前 15 秒）没有专门设计。
- ❌ 分镜行没有写"这一镜观众该记住什么"。
- ❌ CTA 结尾只有"记得三连"没有画面事件。
- ❌ CTA 两个主动作并列（下载 + 关注 + 评论堆一起）。
- ❌ 浅色 AI 概念图直接插进深色屏录序列。
- ❌ 全片无烧录字幕规划（静音观看场景流失）。
- ❌ B-ROLL 行特效模式为空或填写未注册 ID。

## 9. 与阶段2 的衔接

阶段2 读取阶段1 产物的方式：

1. 读取 `STORYBOARD.md` 的 `特效模式` 列，生成节拍表。
2. 对每个绑定的特效 ID：
   - 在 `assets/effects_library/registry.json` 查记录。
   - 读 `assets/effects_library/catalog.md` 对应条目。
   - 读 `assets/effects_library/snippets/<id>.html` 获取代码范式。
3. 按真实时间戳搭建 hyperframes 工程，渲染透明 WebM 特效轨。
4. 用 FFmpeg 合成最终成片。

因此，阶段1 只要保证**分镜表按句、按 ID 绑定准确**，阶段2 就能自动把特效模式翻译为可渲染的 hyperframes 节拍。
