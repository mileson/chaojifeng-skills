# 自动剪辑规则

本文件定义 `video-content-factory` 阶段 2 自动剪辑的去口误、去停顿、去重复、失败开头处理与边界保护规则。

所有规则以 `data/config.yaml` 中的 `clip_edit` 配置为基线，剪辑脚本必须在运行期读取该配置并允许通过命令行参数或工程级 `clip_edit_override` 临时覆盖。

## 与 `data/config.yaml` 的对应关系

```yaml
clip_edit:
  default_aggression: "standard"   # conservative / standard / aggressive
  protect_first_word_guard_ms: 120 # 首词起音保护
  protect_last_word_guard_ms: 180  # 尾词收音保护
  max_silence_to_cut_ms: 300       # 无语音静音段/空白段切除阈值；>0.3s 必须剪掉
```

| 配置项 | 在剪辑规则中的含义 | 默认值 |
| --- | --- | --- |
| `default_aggression` | 全局默认攻击性级别，决定哪些类别的口误/重复/停顿会被自动切除 | `standard` |
| `protect_first_word_guard_ms` | 成片片段起始点不能紧贴在第一个保留词的 ASR 边界上，必须向前预留至少该时长的起音保护 | 120 ms |
| `protect_last_word_guard_ms` | 成片片段结束点不能紧贴在最后一个保留词的 ASR 边界上，必须向后预留至少该时长的收音保护 | 180 ms |
| `max_silence_to_cut_ms` | `standard` 级别下，无语音静音段/空白段超过该时长才整段切除 | 300 ms |

> 规则中提到的“起音/收音保护”均以 ASR 词级时间戳为参考，而非片段边界。若 ASR 没有词级时间戳，则回退到片段的 `segment.start` 与 `segment.end` 并增加 200 ms 安全余量。

## 攻击性级别总览

| 级别 | 定位 | 适合场景 | 核心策略 |
| --- | --- | --- | --- |
| `conservative` | 保守，宁可长一点也不要误伤 | 访谈、知识密度高的长视频、首次交付审阅 | 只切除明显失败开头、过长停顿、完全重复的拍摄片段；保留所有过渡性口水话 |
| `standard` | 默认，兼顾干净与信息完整 | 常规口播、教程、Skill 分享 | 在保守基础上再切除独立口水话、明显自我修正的冗余前段、可识别重复过渡句；保持语义连贯 |
| `aggressive` | 紧凑，短平快 | 短视频（抖音/视频号/小红书）预告、高密度切片 | 大力压缩停顿、多数口水话、重复解释；允许更短的边界保护；所有语义层面的裁剪必须生成 `review_draft.md` 供人工确认 |

## 1. 口水话/填充词（filler）

### 1.1 识别范围

常见中文口播填充词分为两类：

- **语气词**：`嗯`、`呃`、`啊`、`哦`、`哎` 等单音节，以及连读如 `嗯……那个`、`呃……就是`。
- **连接/缓冲词**：`那个`、`就是`、`然后`、`那么`、`其实`、`对吧`、`是不是`、`怎么说呢`、`可以说`、`这样子`、`的话`。

识别条件（同时满足才视为可切除候选）：

1. 词本身在 `data/corrections.yaml` 的 `filler_words` 列表中（若该文件存在）。
2. 该词不构成句子主干：删除后句子主谓宾完整或更通顺。
3. 该词前后存在可切分边界（前后均有其他词或静音段）。
4. 该词不是唯一承载语气/转折的过渡词（如 `但是呢` 后的 `但是` 不可删）。

### 1.2 三级处理规则

| 级别 | 处理规则 | 示例 |
| --- | --- | --- |
| `conservative` | 不主动删除填充词；仅当填充词构成**连续 3 个及以上语气词链**或造成超过 `max_silence_to_cut_ms` 的伴随长停顿时，才切除最长的一个链。 | `嗯……呃……那个……` → 整链切除 |
| `standard` | 删除**独立的单语气词**和**前后带停顿的缓冲词**；保留句首/句尾的过渡性填充（避免跳切）。 | `我们今天要讲的是，呃，自动剪辑。` → 删除 `呃` 及两侧短停顿 |
| `aggressive` | 删除绝大多数填充词，包括成串缓冲词；仅保留带明确转折含义的 `但是`、`不过`、`所以` 等。若删除后会出现生硬跳切，则必须同步切除相邻的短停顿或配合画面过渡。 | `然后呢，我们接下来看……` → 删除 `然后呢，` |

### 1.3 禁止行为

- 不能因为列表里有某个词就机械删除，必须检查上下文语义。
- 不得通过只删字幕文本的方式隐藏填充词，必须生成对应 `word_cut_ranges` 从音画中同步切除。

## 2. 重复/自我修正（repetition & restart）

### 2.1 识别规则

重复分为三种模式：

1. **完全重复**：连续或近邻出现内容几乎相同的整句/短语（文本相似度 ≥ 90%，时间间隔 ≤ 5 秒）。
2. **自我修正重启**：说话人说到一半发现不对，立刻重新组织语言。典型信号：
   - 同一实词连续出现 3 次及以上，如 `这个这个这个`、`我们今天我们今天`。
   - 前半句语义不完整，后半句以 `不对`、`我是说`、`应该是` 等标记开头。
3. **冗余过渡句**：相邻两句表达相同转折/衔接功能，如 `那我们先来看一下第一点。那首先呢我们看一下第一点。`

### 2.2 处理规则

统一遵循 **“删前保后”** 原则：当说话人自我重启时，保留后面更完整、更准确的版本，切除前面不完整或重复的部分。

| 级别 | 处理规则 |
| --- | --- |
| `conservative` | 只处理**完全重复**且时长 ≥ 3 秒的片段；自我修正重启如果后面的重述不超过 2 个词，则保留原样 |
| `standard` | 处理完全重复、明显自我修正重启；对于“短句 + 立即完整重述”的情况，删除前面短句或重复尾词 |
| `aggressive` | 处理完全重复、自我修正、冗余过渡句；允许合并多次重启为一次最完整表述；必须写入 `review_draft.md` |

### 2.3 判定示例

| 原话（ASR） | 决策 | 原因 |
| --- | --- | --- |
| `今天我们要讲的是自动剪辑规则，今天我们要讲的是自动剪辑规则。` | 删除第一次出现的整句，保留第二次 | 完全重复 |
| `这个这个这个规则主要是用来……` | 删除前两个 `这个`，保留第三个 | 连续口吃式重复 |
| `我们今天要讲的是，不对，我们今天要聊的是剪辑规则。` | 删除 `我们今天要讲的是，不对，` | 失败开头 + 自我修正 |

## 3. 停顿/静音（pause & silence）

### 3.1 识别规则

停顿基于 ASR 片段或词级时间戳计算：

- **无语音静音段**：两相邻词之间 `next.start - prev.end` 没有语音活动。
- **片段间空白**：ASR 返回的两个 `segment` 之间存在 `> 200 ms` 的间隙。
- **段落停顿**：出现自然换气、思考、翻页等导致的长静音。

> 若 ASR 未返回词级时间戳，使用 `segment` 级间隙并减去 100 ms 对齐余量作为估算。

### 3.2 用户显式空白切除规则

当用户明确要求「空白/静音段超过 0.3 秒必须剪掉」时：

1. `max_silence_to_cut_ms` 统一设为 300 ms，`standard` 与 `aggressive` 均执行该阈值。
2. 切除后若相邻保留区间之间的剩余间隙 < 250 ms，必须合并为一个保留片段，避免产生微小跳切和黑场。
3. 若 300 ms 的静音位于句内换气且前后语义连贯，优先切除后保留 200 ms 自然停顿；若静音由思考、翻页等造成，整段切除。

### 3.3 三级处理规则

| 级别 | 静音段长度 | 处理方式 |
| --- | --- | --- |
| `conservative` | > 1200 ms | 切除超过部分，保留 400 ms 自然停顿；≤ 1200 ms 保留 |
| `standard` | > `max_silence_to_cut_ms`（默认 300 ms） | 切除超过部分，保留 200 ms 自然换气停顿；≤ 300 ms 保留 |
| `aggressive` | > 300 ms | 切除超过部分，仅保留 150–200 ms 短促停顿 |

### 3.4 特殊保护

以下停顿不得切除，即使长度超过阈值：

- 停顿前后为**戏剧性强调、悬念、笑点**（需结合 `STORYBOARD.md` 的 `特效模式` 或人工标记）。
- 停顿出现在**片头问候与正文之间**的首次开场留白（保留 ≤ 1 秒）。
- 用户通过工程文件显式声明 `protect_pauses: [start, end]` 的区间。

## 4. 失败开头（false start）

### 4.1 识别规则

失败开头指说话人开始表达后放弃原句并重新组织语言的现象，常见形式：

| 类型 | 识别信号 | 示例 |
| --- | --- | --- |
| 开场尝试 | 视频开头 10 秒内出现多次不完整开场，伴随长停顿或自我修正 | `大家好，我是……呃，大家好，我是超级峰。` |
| 中途卡壳 | 句子中间出现 3 次以上同一实词重复或明显口吃 | `这个这个这个接口它主要是……` |
| 语义放弃 | 句子未完，出现 `不对`、`重来`、`我是说`、`应该是` 等标记后重启 | `我们今天要讲的是脚本，不对，是剪辑规则。` |

### 4.2 处理规则

| 级别 | 规则 |
| --- | --- |
| `conservative` | 只删除视频开头 **2 秒内** 的明显失败尝试；中途卡壳若不影响语义保留 |
| `standard` | 删除所有识别到的失败开头，保留重启后的完整句子；若删除后留下 > 300 ms 无词间隙，需同步切除间隙 |
| `aggressive` | 删除失败开头并允许合并多次重启后的最终表述；若失败开头后的重启仍不理想，可进一步切除，必须生成 `review_draft.md` |

### 4.3 边界保护

- 删除失败开头后，成片必须从第一个保留词的起音保护之前开始，不得直接从被删除的词边界切入。
- 若失败开头发生在片段中间，删除后前后两个保留片段的衔接处必须检查是否存在呼吸声、吞咽声等无词音频，必要时增加过渡帧或切除。

## 5. 边界保护（boundary protection）

### 5.1 首词起音保护

- 每个成片片段的起始点，不得等于其第一个保留词的 ASR `start` 时间。
- 必须向前预留 `protect_first_word_guard_ms`（默认 120 ms），除非：
  - 前推会越过视频起点或上一个切除区间。
  - 前推会恢复已删除的填充词/失败开头。
- 若预留后覆盖了其他保留词，则只保留到该词开始前的最小安全距离。

### 5.2 尾词收音保护

- 每个成片片段的结束点，不得等于其最后一个保留词的 ASR `end` 时间。
- 必须向后预留 `protect_last_word_guard_ms`（默认 180 ms），除非：
  - 后延会越过视频结尾。
  - 后延会与下一个保留词或保留片段发生重叠。
- 若后延进入下一个词，则只保留到下一个词开始前的最小安全距离。

### 5.3 片段间拼接保护

- 当两个保留片段相邻且中间只删除了短填充词/静音时，优先合并为一个成片片段，避免产生微小跳切。
- 执行 0.3s 空白切除后，若相邻保留片段之间的剩余间隙 < 250 ms，必须合并为一个成片片段，防止黑场/闪烁。
- 若必须分段（如中间删除了语义内容），应保证拼接点两侧都有足够的起音/收音保护，避免出现吞音或爆音。

### 5.4 去间隙清理

每次生成剪辑决策后，必须执行一次边界清理：

1. 检查每个保留片段内部是否存在无词音频间隙（由删除词造成），间隙 > 200 ms 时标记为额外 `word_cut_ranges`。
2. 检查保留片段首尾是否存在吞咽声、呼吸声，必要时扩展切除范围，但不得侵犯起音/收音保护。
3. 检查最终字幕时间轴，确保被切除的词不再出现在字幕中。

## 6. 剪辑决策文件 `edit_decisions.json`

自动剪辑完成后必须输出 `edit_decisions.json`，作为后续重新渲染、审阅、回滚的依据。

```json
{
  "aggression": "standard",
  "config_source": "data/config.yaml",
  "source_duration_ms": 125430,
  "segments": [
    {
      "segment_id": 0,
      "source_start_ms": 520,
      "source_end_ms": 18400,
      "output_start_ms": 0,
      "output_end_ms": 17880,
      "reason": "kept",
      "cuts": []
    },
    {
      "segment_id": 1,
      "source_start_ms": 19200,
      "source_end_ms": 45200,
      "output_start_ms": 17880,
      "output_end_ms": 43680,
      "reason": "kept_with_cuts",
      "cuts": [
        {
          "type": "filler",
          "source_start_ms": 23100,
          "source_end_ms": 23550,
          "text": "呃",
          "confidence": 0.95
        },
        {
          "type": "silence",
          "source_start_ms": 31200,
          "source_end_ms": 32300,
          "compress_to_ms": 300
        }
      ]
    }
  ],
  "removed_ranges": [
    {
      "source_start_ms": 18400,
      "source_end_ms": 19200,
      "type": "silence",
      "reason": "long_pause"
    }
  ]
}
```

### 字段说明

| 字段 | 说明 |
| --- | --- |
| `aggression` | 生成本次决策时使用的攻击性级别 |
| `config_source` | 配置来源路径，便于追溯 |
| `source_duration_ms` | 原始视频总时长 |
| `segments` | 保留到成片中的连续片段列表 |
| `segments[].source_start/end_ms` | 在原始视频中的起止时间（含边界保护） |
| `segments[].output_start/end_ms` | 在成片中的起止时间 |
| `segments[].cuts` | 该保留片段内部执行的细粒度切除/压缩 |
| `removed_ranges` | 被整段删除的区间（失败开头、完全重复、过长静音等） |
| `confidence` | 自动决策置信度，0–1；低于 0.7 的语义类切除应进入 `review_draft.md` |

## 7. 质量门控

剪辑完成后必须通过以下检查才能进入特效合成阶段：

1. **隐藏语音检查**：最终字幕中出现的文字必须能被保留的音画覆盖；任何被删除但字幕仍保留的词都必须修正。
2. **零长度检查**：所有 `segments` 和 `cuts` 的时间范围必须 `end > start`。
3. **连续性检查**：`output_end_ms` 必须等于下一个 `output_start_ms`，不得出现重叠或黑场。
4. **首末保护检查**：第一个片段的 `source_start_ms` 必须 ≤ 第一个保留词 `start - protect_first_word_guard_ms`（或视频起点）；最后一个片段的 `source_end_ms` 必须 ≥ 最后一个保留词 `end + protect_last_word_guard_ms`（或视频结尾）。
5. **review_draft 检查**：`aggressive` 级别或任何置信度 < 0.7 的语义切除，必须生成 `review_draft.md` 并列明原始时间码、切除原因、建议是否保留。

## 8. 快速参考表

| 规则项 | `conservative` | `standard`（默认） | `aggressive` |
| --- | --- | --- | --- |
| 独立语气词 | 不删 | 删除 | 删除 |
| 缓冲连接词 | 不删 | 仅删带停顿的 | 删除 |
| 完全重复 | 时长 ≥ 3 秒才删 | 删除 | 删除 |
| 自我修正重启 | 几乎不删 | 删除前段 | 删除并合并 |
| 失败开头 | 仅删开头 2 秒内 | 删除 | 删除并审阅 |
| 停顿切除阈值 | 1200 ms | 300 ms（配置值） | 300 ms |
| 起音保护 | 120 ms（配置值） | 120 ms（配置值） | 120 ms，可审阅后降至 80 ms |
| 收音保护 | 180 ms（配置值） | 180 ms（配置值） | 180 ms，可审阅后降至 120 ms |
| 必须审阅 | 否 | 置信度 < 0.7 时 | 是 |

## 9. 例外与人工覆盖

- 用户可以通过工程目录下的 `clip_edit_override.yaml` 覆盖 `default_aggression`、`max_silence_to_cut_ms`、保护时长等配置。
- `STORYBOARD.md` 中若某句标记 `protect_audio: true`，则该句范围内禁止任何自动剪辑，仅允许校正字幕。
- 遇到笑声、现场互动、方言口癖等不确定情况时，默认降级到 `conservative` 并生成 `review_draft.md` 供人工决策。
