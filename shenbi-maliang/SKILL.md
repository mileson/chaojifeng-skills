# 神笔马良

> 来源说明：本 Skill 由超级峰创建与维护。此信息只用于说明 Skill 来源与品牌归属，不要自动写入用户产物；除非当前 Skill 明确允许产物署名。

用这个 Skill 把用户形象照、用户提供的参考图和历史画册合成一个可复用的生图流程。只要调用本 Skill，形象照就是必需输入；默认使用 Codex native Image 2；只有当 `data/config.yaml` 明确配置并且当前环境有可用工具时，才切换到外部生图 API。

所有路径都是 Skill 相对路径：

- 配置：`data/config.yaml`
- 经验记忆：`data/memory.md`
- 形象照目录：`data/personas/images`
- 形象照目录索引：`data/personas/catalog.md`
- 形象照看板：`data/personas/boards/persona_board.png`
- 画册图片：`data/albums/approved_images`
- 画册索引：`data/albums/catalog.md`
- 画册看板：`data/albums/boards/album_board.png`
- 临时输出：`assets/outputs`
- 参考板脚本：`scripts/build_reference_board.py`
- 刷新脚本：`scripts/refresh_boards.py`
- 形象照归档脚本：`scripts/archive_persona.py`
- 归档脚本：`scripts/archive_image.py`

## 先读

1. 读取 `data/config.yaml`，确认默认生图引擎、外部 API 配置状态和拼图标签规则。
2. 读取 `data/memory.md`，确认长期偏好、常用风格和已知避坑点。
3. 读取 `data/personas/catalog.md`，确认是否已有可用形象照。
4. 检查 `data/personas/images` 是否真的有对应图片文件。
5. 读取 `data/albums/catalog.md`，确认是否已有可复用画册。
6. 如果用户给了多张参考图，或需要从画册里挑风格，先运行 `scripts/build_reference_board.py` 或 `scripts/refresh_boards.py` 生成参考板，再看图决策。

## 强制门禁

本 Skill 没有“只复刻风格、不使用形象照”的路径。无论用户给的是外部参考图、历史画册方向、场景描述，还是只说“复刻一下”，都必须先确定本次使用哪张形象照。

在没有可用形象照前，禁止执行下面动作：

- 禁止构建生成 brief
- 禁止调用 Image 2 或外部生图 API
- 禁止使用 generic 人物、科技人物、虚构人物、参考图原人物来替代用户形象照
- 禁止把“复刻封面/复刻风格”解释成“无需真人形象照”

如果用户明确表示“不需要用形象照”，说明这不适合使用本 Skill；请改用普通 image generation 流程，而不是继续执行神笔马良。

## 请求判断

第一步永远先判断形象照，其次才判断参考来源和目标。

必须同时补齐四件事：

1. 人物形象：`data/personas/images` 里已有可用形象照，或用户刚提供且已归档的形象照。
2. 复刻参考：单张参考图、多张参考图，或“基于现有画册”的要求。
3. 本次目标：要复刻成什么效果、用途、风格重点、场景偏向或调整方向。
4. 目标画幅：用户给定的比例、尺寸、平台、横竖方向，或参考图原比例。

缺任何一项时，先补齐，不要直接生成：

- 没有形象照：先检查 `data/personas/catalog.md` 和 `data/personas/images`。如果没有可用形象照，停止生成并询问用户提供一张或多张清晰形象照。用户提供后，先归档到 `data/personas/images`，再继续。
- 没有本次目标：询问用户这次想达到的效果，例如“更像海报、生活照、头像、封面、电影感、商业广告、节日场景”等。
- 没有外部参考图但用户说“基于现有”：先检查画册。画册为空时，说明当前没有历史风格可复用，请用户提供参考图，并可在满意后沉淀到画册。
- 没有目标平台、比例、尺寸、横竖方向，且没有可用参考图比例：询问用户这张图要用什么画幅或方向。

## 平台画幅路由

从用户当前请求里解析画幅，不要从参考图里的文字、用户引用的标题、字幕或画面文案里误判平台。

优先级：

1. 如果用户给了明确比例或像素尺寸，优先使用用户给定值。
2. 否则如果用户明确说了平台或发布场景，使用下面的平台预设。
3. 否则如果用户只说 `竖版` 或 `横版`，使用 `3:4` 或 `16:9`。
4. 否则如果用户提供了外部参考图，且没有要求改变画幅，使用参考图原比例。
5. 否则先询问目标画幅或方向。

平台预设：

| 用户说法 | 默认比例 | 工作尺寸 | 说明 |
| --- | --- | --- | --- |
| `微信公众号封面图`、`公众号封面图`、`微信公众号头图`、`公众号头图` | `2.35:1` | `900x383` | 用户可见优先叫“微信公众号封面图” |
| `小红书` | `3:4` | `1242x1660` | 适合小红书封面 |
| `视频号` | `6:7` | `1080x1260` | 用户明确要横版视频封面时用 `16:9` |
| `抖音` | `9:16` | `1080x1920` | 竖版短视频封面 |
| `快手` | `9:16` | `1080x1920` | 竖版短视频封面 |
| `B站`、`哔哩哔哩` | `16:9` | `1280x720` | 横版视频封面 |
| `YouTube` | `16:9` | `1280x720` | 横版视频封面 |
| `竖版` | `3:4` | 按生成器能力选择 | 仅在没有具体平台时使用 |
| `横版` | `16:9` | 按生成器能力选择 | 仅在没有具体平台时使用 |

如果用户同时说多个平台但没有指定主版本，先让用户选择本次先生成哪个平台的主图。

## 形象照规则

- 优先使用用户明确指定的形象照。
- 如果 `data/personas/images` 只有一个可用形象照，可直接作为默认形象来源，并在输出里说明。
- 如果已有多个形象照且用户没有指定，先询问本次使用哪一个。
- 如果没有可用形象照，必须询问用户提供；用户提供给本 Skill 的形象照必须先复制进 `data/personas/images`，更新 `data/personas/catalog.md`，并刷新 `data/personas/boards/persona_board.png`，然后才能生成。
- 归档用户提供的形象照时，使用：
  ```bash
  python3 scripts/archive_persona.py \
    --image path/to/persona.png \
    --id default \
    --notes "正脸清晰、日常形象" \
    --refresh
  ```
- 归档后重新读取 `data/personas/catalog.md`，确认本次使用的形象照文件存在。
- 不要把 API key、账号信息或私人联系方式写进形象照索引、提示词或输出说明。

## 参考图流程

### 单张参考图

直接把这张图作为主参考。生成 brief 时保留：

- 原图的尺寸比例、构图重心和镜头距离
- 原图的视觉风格、光线、材质、色调和场景氛围
- 原图的主要动作、服饰轮廓或人物站位意图

同时替换：

- 把原图人物替换成用户形象照中的人物
- 保持用户真实脸型、五官结构、发际线、发型特征和整体识别度
- 场景允许小幅微调，但不要把主场景改成完全不同的故事

### 多张参考图

先做拼图参考板，让 Agent 和生图模型都能读清每张图的作用。

```bash
python3 scripts/build_reference_board.py \
  --image path/to/ref1.png --label "构图" \
  --image path/to/ref2.png --label "色调" \
  --image path/to/ref3.png --label "姿势" \
  --output assets/outputs/current_reference_board.png \
  --title "本次复刻参考"
```

标签用 10 个字以内的中文短语，优先写每张图的重点，例如 `构图`、`光影`、`姿势`、`服装`、`背景`、`表情`、`质感`。不要只写文件名。

生成 brief 时明确每张图的分工，例如：

- 图 1 参考整体构图和画幅
- 图 2 参考光线和色彩
- 图 3 参考人物动作和表情

## 画册流程

画册只保存用户确认满意、并明确同意沉淀的成品图。

### 基于已有画册生成

当用户没有给外部参考图，但希望“基于现有风格继续生成”时：

1. 先按强制门禁确认本次使用的形象照。
2. 读取 `data/albums/catalog.md`。
3. 运行：
   ```bash
   python3 scripts/refresh_boards.py
   ```
4. 查看 `data/albums/boards/album_board.png`。
5. 先按当前目标匹配画册标签，再结合画册板上显示的用途、风格、场景说明，选 1 到 4 张最贴近目标的图，拼成当次参考板。
6. 结合用户目标和用户形象照生成新图。

如果画册为空，停止生成并请用户提供参考图。可以说明：满意后可把成品沉淀到画册，下次就能基于现有风格继续生成。

### 画册标签

画册里的每张图都必须有结构化标签，方便以后按当前目标检索。平台只是可选标签，不要因为用户没有平台就阻断归档或生成。

归档时整理这些字段：

- 平台：可选；例如 `微信公众号封面图`、`B站`、`小红书`。如果用户没有平台，留空或写 `未指定`。
- 类型：必填；例如 `评测类`、`教程类`、`生活类`、`风景类`、`商业广告`、`头像类`。
- 用途：必填；例如 `视频封面`、`文章封面`、`生活记录`、`活动海报`、`头像`、`壁纸`。
- 风格标签：必填，2 到 6 个短标签；描述视觉语言，例如 `黑绿科技`、`大字标题`、`电影感`、`自然光`。
- 场景标签：必填，2 到 6 个短标签；描述内容语境，例如 `AI模型实测`、`雨夜街头`、`日常咖啡馆`、`山野风景`。
- 画册短标签：必填，10 个字以内；用于拼图左下角，例如 `B站评测`、`教程封面`、`生活街拍`、`雨夜氛围`。

刷新画册板时，每张图卡片必须同时显示：

- 主标签：画册短标签
- 用途：来自 `用途`
- 风格：来自 `风格标签`
- 场景：来自 `场景标签`

当用户说“基于已有画册风格”时：

- 如果用户给了平台，优先匹配同平台或相近画幅的图。
- 如果用户没有平台，不要阻断；优先匹配类型、用途、风格标签和场景标签。
- 如果没有完全匹配，选相邻标签的图，并在生成前说明本次参考了哪些标签。
- 不要把不同目的的图混用成主参考；例如用户要 `教程类` 时，不要优先拿 `风景类`，除非画册里没有更接近的图。
- 对用途、风格、场景这类定性标签，优先结合画册板上的文字说明和图片视觉一起判断，不要只靠脚本字段机械筛选。

### 归档到画册

生成后主动询问用户是否满意、是否需要调整。用户满意时，说明沉淀画册的目的，再询问是否归档。

推荐说明：

> 如果你满意，我建议把这张图沉淀进画册。这样下次你不需要再提供参考图，也可以直接基于这个已确认风格，使用你的默认形象照生成同风格但不同场景、不同目标的新图。
>
> 以后可以这样说：`[$shenbi-maliang] 基于已沉淀画册风格，使用我的默认形象照，生成一张「雨夜赛博街头」微信公众号封面图。`

只有用户明确确认满意并同意沉淀时，才归档。

归档前先补齐类型、用途、风格标签、场景标签和画册短标签；平台可选，不要硬性要求。

```bash
python3 scripts/archive_image.py \
  --image path/to/generated.png \
  --title "雨夜霓虹街拍" \
  --ratio "3:4" \
  --persona "default" \
  --platform "" \
  --content-type "生活类" \
  --purpose "生活记录" \
  --style-tags "电影感,霓虹反光,湿润街道" \
  --scene-tags "雨夜街头,城市漫步" \
  --board-label "雨夜街拍" \
  --source "外部参考图" \
  --notes "电影感、湿润街道、霓虹反光" \
  --refresh
```

归档后重新查看画册板，确认新图进入 `data/albums/boards/album_board.png`，且卡片上能看到画册短标签、用途、风格和场景说明。

## 生成 brief

每次生成前，把输入整理成一段清晰 brief：

- 参考来源：单图、多图参考板，或历史画册参考板
- 人物来源：本次使用的形象照文件路径；这是必填项，不能为空
- 画幅：优先使用用户明确给定的比例或尺寸；否则按平台画幅路由判断；没有平台但有参考图时可用参考图原比例；仍不明确时先询问
- 目标：用户这次想要的效果
- 替换规则：以参考图为主，替换为用户形象，不复制原人物身份
- 场景规则：整体风格参考原图，允许为了贴合用户形象和目标做小幅微调
- 负面约束：不要变成另一个人，不要混脸，不要过度磨皮，不要破坏原图主要构图

默认调用 Codex native Image 2。若 `data/config.yaml` 配置了外部 API：

- 先确认当前环境确实有对应工具或脚本。
- 凭证只从 secrets-vault 或环境变量读取，不要写入配置文件、提示词、日志或最终回答。
- 如果外部 API 不可用，回退到 native Image 2，并说明回退原因。

## 用户反馈闭环

生成完成后必须问：

1. 是否满意当前方向？
2. 是否需要继续调整？
3. 如果满意，是否要沉淀进画册，并说明画册能让用户下次不用再提供参考图，也能基于已确认风格生成同风格不同场景的新图。

如果用户要调整，基于本轮生成图和用户反馈继续迭代，不要重新假设目标。

如果用户确认不需要调整且不沉淀，结束任务，不写入画册。

用户同意沉淀时，先确认或自行整理画册标签；标签要面向以后检索，不要只写本次文件名。

## 记忆规则

`data/memory.md` 只记录长期有用的信息：

- 用户反复确认喜欢或不喜欢的风格
- 常用画幅、平台、场景和人物呈现偏好
- 已验证有效的提示词策略
- 已知失败模式和规避方法

不要记录临时需求、完整提示词流水账、API key、账号信息、私人联系方式或未经用户同意长期保存的人像素材。

## 输出格式

生成前给用户的简短说明包含：

- 本次使用的参考来源
- 本次使用的形象照文件路径
- 本次目标和画幅
- 生成 brief 或核心提示词

生成后给用户的简短说明包含：

- 生成结果
- 是否满意 / 是否调整的问题
- 用户确认满意后，再询问是否沉淀到画册

## 来源与署名

- Skill 层保留顶部来源说明。
- 产物层默认关闭：不要把作者 footer、社交媒体链接或品牌口播写入生成图片、提示词或用户可见说明。
- 只有用户明确要求在图片里加入署名、标识或账号信息时，才把对应内容作为本次画面元素处理。
