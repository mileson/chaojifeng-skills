# 完整清单与分片

任何大型首次扫描之前使用本参考。

目标是避免遗漏文件、避免重复处理，并决定并行子代理分片是否值得。

## 核心规则

不要立刻开始全面分类。

先建立文件夹的**完整清单基线**，然后决定：

1. 单代理还是并行子代理
2. 如何分片
3. 如何验证没有文件被漏掉

## 第 1 步 — 建立清单基线

协调者先收集：

- 文件总数
- 目录总数
- 顶层目录
- 各顶层目录的文件数
- 扩展名分布
- 根级散落文件
- 隐藏/系统文件数

这在任何 worker 开始分析之前给团队一个稳定基线。

## 清单产出

清单应让协调者能回答：

- 文件夹有多大
- 最大的簇在哪里
- 文件夹是干净的还是混杂的
- 问题规模是否足以启用并行 worker

至少保留：

- `total_files`
- `total_dirs`
- `files_by_top_level_dir`
- `files_by_extension`
- `root_level_file_count`
- `hidden_or_system_file_count`

## 为什么重要

没有基线时，worker 可能：

- 漏掉整个分支
- 在相同路径上重复工作
- 过度关注关键词密集的显眼目录
- 覆盖不足那些安静但重要的文件夹

## 第 2 步 — 决定单代理还是并行子代理

### 优先单代理，当

- 文件数量适中
- 角色明显
- 文件夹结构已经干净
- 只需要刷新

### 优先并行子代理模式，当

- 文件数量大
- 顶层分支众多
- 文件夹混合了内部与客户/项目材料
- 角色含糊
- 合规、资产、业务材料混杂

## 强制阈值

以下是本 skill 的执行门禁：

- `total_files > 3000` → 必须并行子代理模式
- `meaningful_top_level_branches > 8` → 必须并行子代理模式
- 客户/项目 + 合规 + 资产信号混杂 → 必须并行子代理模式
- 清单初筛后角色置信度低或中 → 必须并行子代理模式

低于这些阈值时允许单代理模式，但不是必须。

## 第 3 步 — 按目录分片，不按关键词

首轮覆盖按**目录切片**分片，不按语义关键词切片。

好的分片：

- Worker A 负责一个顶层子树
- Worker B 负责另一个子树
- Worker C 负责再一个子树

坏的分片：

- 一个 worker 扫“PRD”
- 一个 worker 扫“合同”
- 一个 worker 扫“风险”

关键词分片在后期做定向检查有用，但作为主要覆盖策略偏弱。

## 推荐分片策略

### 第一层

协调者按顶层或接近顶层的目录分组。

### 第二层

按以下因素大致平衡分片：

- 文件数
- 业务复杂度
- 明显风险

### 第三层

给 worker 分配有边界的归属，例如：

- Worker A：产品 / 项目 / 交付文件夹
- Worker B：客户 / 销售 / 外部项目文件夹
- Worker C：财务 / 人事 / 法务 / 行政文件夹
- Worker D：历史归档 / 混杂遗留文件夹

## Worker 归属规则

每个 worker 应收到：

- 归属路径
- 排除路径
- 目标问题
- 要求的输出格式

这可以避免重叠并改善覆盖率核算。

## 第 4 步 — 覆盖率核算

最后，协调者必须对比：

- `inventory_total`
- `processed_unique_total`
- `skipped_total`
- `unassigned_total`
- `duplicate_total`

目标：

- `inventory_total = processed_unique_total + skipped_total`
- `unassigned_total = 0`
- `duplicate_total = 0`

## 覆盖率检查清单

综合分析之前验证：

- 每个顶层分支都已分配
- 根级散落文件没有被遗忘
- 隐藏/系统文件是有意跳过的，不是意外忽略的
- 没有 worker 上报了其分片之外的路径
- 没有顶层分支处于零归属状态

## 建议的内部状态文件

这些不需要交付给最终用户，是协调者的工作状态。

### `scan.summary.json`

保存：

- 文件总数
- 目录总数
- 分片候选
- 扩展名分布

### `scan.assignment.json`

保存：

- worker 名称
- 归属路径
- 排除路径
- 每个分片的预期文件数

### `scan.coverage.json`

保存：

- 已处理文件数
- 已跳过文件数
- 重复数
- 未分配数

## 必需的团队流程

1. 协调者建立清单基线
2. 协调者决定单代理还是并行子代理模式
3. 若并行子代理模式，协调者按目录分片
4. 子代理只检查自己的分片
5. 协调者合并结果
6. 协调者做覆盖率检查
7. 之后才询问用户并生成产出

## 重要规则

覆盖率优先于精致度。

有完整覆盖的略粗糙的早期分类，好过漏掉一整个分支文件的精致但不完整的分类。

## 重要禁令

命中强制阈值时，协调者不得：

- 在单个清单 worker 之后就停止
- 清单之后立即询问用户
- 清单之后立即生成 HTML
- 跳过分片和覆盖率核算
