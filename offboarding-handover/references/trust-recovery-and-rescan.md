# 信任恢复与重新扫描

当前会话疑似存在部分状态、过期状态或不可信的中间输出时，使用本参考。

目标是阻止代理在证据薄弱时假装某个阶段已经完成。

## 核心原则

不要自动信任中间状态。

信任必须由证据换取。

证据薄弱时，工作流应回退到：

- 恢复较早的阶段
- 重跑缺失的阶段
- 或强制全新扫描

## 什么算中间状态

例如：

- `.offboarding-handover/offboarding.config.json`
- `.offboarding-handover/handover.answers.json`
- `.offboarding-handover/handover.manifest.json`
- 清单摘要
- 分片分配
- 覆盖率文件
- 已存在的 HTML 输出

## 信任级别

### 高信任

仅当满足以下条件时直接使用既有状态：

- 状态文件存在
- 与当前预期结构匹配
- 内部一致
- 足够贴近当前文件夹状态
- 没有迹象表明某个必要阶段被跳过

### 中信任

仅当出现以下情况时把状态当作提示：

- 存在部分状态，但不完整
- 部分预期文件缺失
- 输出存在但缺少清晰的生成证据
- manifest 存在但缺少覆盖率证据

此时：

- 复用安全的部分
- 重跑缺失的阶段

### 低信任

出现以下情况时，把当前状态视为不具权威性：

- 脚手架文件缺失或明显过期
- manifest 存在但输出缺失，且生成链条不清晰
- 清单存在，但本应触发并行子代理模式却没有触发
- 用户明确要求“仔细调研”、“重新扫描”、“重新看看效果”等
- 当前文件夹结构与记录的状态不再匹配

此时：

- 从较早阶段重跑
- 必要时优先走全新的首次扫描路径

## 重扫触发条件

满足以下任一条件时，至少强制部分重扫：

- `handover.manifest.json` 缺失
- 输出目录缺失且没有可信的渲染痕迹
- 清单基线缺失
- 已触发并行扫描但缺少覆盖率证据
- 命中并行阈值但实际启动的专职子代理少于 2 个
- 顶层分支与记录的基线有实质差异
- 文件数量与记录的基线有实质差异

## 阶段恢复规则

### Phase 1 不可信时

回到：

- Phase 1 — 清单基线

### Phase 2 触发决策不可信时

回到：

- Phase 1 或 2，取决于清单是否仍可信

### Phase 3 扇出不可信时

回到：

- Phase 3 — 并行子代理扇出

不得继续进入提问或渲染。

### Phase 4 综合不可信时

回到：

- Phase 4 — 综合分析与覆盖率检查

### Phase 5 回答不可信时

回到：

- Phase 5 — 询问用户

### Phase 6 渲染不可信时

回到：

- Phase 6 — 渲染

## 强恢复规则

如果命中了硬触发规则，但当前证据只有：

- 清单
- 或清单 + 一个 worker

那么 Phase 3 必须视为未完成。

不得把它重新解读为“已经够用”。

## 推荐话术模式

信任度低时，代理应明确说出来。

例如：

- `当前中间状态可信度不足，我将回退到清单基线阶段重新核对。`
- `已命中并行条件，但缺少足够的 subagent 执行证据。我将重新进入并行扫描阶段。`
- `manifest 存在，但 coverage 证据不足，因此我不会直接复用它来生成最终交接包。`
