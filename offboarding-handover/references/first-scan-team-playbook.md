# 首次扫描团队手册

首次扫描规模过大或过于含糊、单代理无法自信分类时，使用本手册。

这是 offboarding-handover skill 推荐的执行模式。

## 目标

生成第一版精修 HTML 之前，团队应回答：

1. 这个文件夹最可能属于哪个角色或角色族
2. 材料主要是内部、客户/项目，还是混合
3. 存在哪些未完成工作
4. 存在哪些资产、权限和合规风险
5. 渲染之前至少要问哪些问题

在这一切之前，协调者应按 `references/full-inventory-and-sharding.md` 建立完整清单基线。

## 硬触发规则

清单基线建立后，满足以下任一条件时协调者**必须**进入并行子代理模式：

- 文件总数大于 3000
- 有效顶层分支大于 8
- 内部材料、客户/项目材料、风险/合规信号同时出现
- 可能角色的置信度不高

以上均不满足时，允许单代理模式。

## 子代理形态

使用 **1 个协调者 + 至多 4 个子代理**。

### 协调者

负责：

- 启动与 worker 分配
- 只读取最少量必要的参考
- 冲突消解
- 综合分析
- 设计问用户的问题
- 最终渲染决策

### Worker A — 角色探测器

负责：

- 可能角色的推断
- 置信度与含糊边界
- 支撑角色判断的关键信号

阅读：

- `references/role-detection-and-ask-user.md`
- `references/agent-classification.md`

### Worker B — 项目与领域映射器

负责：

- 按项目、产品线、客户、内部专项或历史归档聚类
- 确定 `03-专项交接` 下应有哪些主区块

阅读：

- `references/default-taxonomy.md`
- `references/agent-classification.md`

### Worker C — 风险与资产检查器

负责：

- 账号
- 权限
- 设备
- 凭证
- 法务/合规信号
- 敏感材料

阅读：

- `references/high-risk-missed-items.md`
- `references/default-taxonomy.md`

### Worker D — 进行中事项与缺失事实探测器

负责：

- 未完成工作
- 待定状态
- 可能的 `待补充` 字段
- 首轮问题候选

阅读：

- `references/first-run-questions.md`
- `references/update-mode.md`

## 执行步骤

### 第 0 步 — 协调者清单基线

协调者先建立轻量但完整的清单：

- 文件总数
- 目录总数
- 顶层分支
- 各分支文件数
- 扩展名分布

然后决定继续单代理还是切换到并行子代理模式。

### 第 1 步 — 协调者初筛

先做非常轻量的扫描。

文件夹明显小而干净时，允许单代理模式。

命中硬触发规则时，并行子代理模式为强制。

### 第 2 步 — 并行启动子代理

每个 worker 检查不同的关注点，大文件夹还应有边界明确的路径归属。

**只有一个后台代理不算并行子代理模式。**

并行子代理模式意味着：

- 一个协调者
- 加至少 2 个并行子代理

推荐目标：

- 1 个协调者 + 4 个子代理

启动之前，协调者应用自然语言显式宣布扇出步骤。

推荐宣布模式：

- `清单基线已完成，已命中并行扫描条件。现在我将并行调用以下 subagents：role-detector、project-mapper、risk-checker、missing-facts-detector。`

只需要两三个时，也应显式点名。

坏模式：

- 悄悄启动一个额外 worker
- 只说 `继续扫描`
- 暗示仅清单就已满足并行要求

### 第 3 步 — worker 输出

每个 worker 必须返回：

- `scope`
- `findings`
- `confidence`
- `conflicts`
- `questions`

### 第 4 步 — 协调者综合

协调者把输出合并为：

- 可能的角色
- 可能的行业适配层
- 可能的文件夹划分
- 可能的高风险清单
- 最小的问用户问题集

### 第 5 步 — 覆盖率检查

问用户之前，协调者验证：

- 所有有效分支都已覆盖
- 没有丢掉主要路径切片
- 重复归属已被理解

### 第 6 步 — 询问用户

问避免低质量首版 HTML 所需的最小高价值问题集。

优先：

- 角色/工作类型问题
- 内部 vs 客户/项目问题
- 未完成工作问题
- 资产/敏感内容问题
- 关键人员与日期问题

### 第 7 步 — 生成

回答收集完成之后才：

- 更新配置
- 更新回答状态
- 构建 manifest
- 渲染 markdown
- 渲染 HTML
- 清理空目录

## 协调者的输出契约

生成之前，协调者应能说清：

- 可能的角色：
- 可能的行业：
- 客户/项目占比：
- 风险画像：
- 未回答的关键事实：
- 接下来要问的问题：

## 重要规则

worker 不得并行写最终交接输出。

只有协调者应更新：

- 配置
- 回答
- manifest
- 最终 markdown 页面
- HTML

这可以避免合并冲突和不一致的交接状态。

## 永不跳过的规则

- 永远不要把仅有清单当作足够的并行执行
- 触发并行子代理模式后，永远不要从清单直接跳到最终生成
- 永远不要在 worker 发现被综合之前问用户
- 永远不要在没有覆盖率检查的情况下宣布首次扫描完成
