# 排障与验证边界

## 先分类，再修正

- 角色像玩具：检查人体比例、拓扑和资产质量。加贴图或增加骨骼数不会自动解决造型问题。
- 图像看着精致但转身像纸片：检查是否用了角色 billboard。用户要真实三维时回到实体网格和蒙皮。
- 骨架存在但不变形：检查 Armature 指向、渲染开关、骨骼对应顶点组和正权重；通过局部骨骼变化与 mesh readback 再验证。
- 眨眼无效或睫毛悬空：检查控制值、驱动、眼睑骨骼和附属网格的表情传递。MPFB 的第二资产根需要正确配置，不能忽略找不到 MHCLO 的警告。
- 握持有空隙：检查道具真正的局部原点、旧旋转/缩放、手腕朝向与指尖目标；不要只移动整个人物凑位置。
- 肘部朝错方向：检查骨骼轴向、链长、极向和锁定的扭转段；用有限角度测试和视觉检查校准。
- 角色变大或漂浮：在服装遮罩影响包围盒前记录人体基准高度，再检查穿鞋后的实际接地位置。
- 材质突然消失：某些资产服务清理没有用户的孤立材质。先挂载材质或临时设 fake user，避免只保留 Python 引用。
- EEVEE/Cycles 耗时不符预期：读实际每帧日志和资源压力；先用代表帧比较收益，再决定参数。不得靠复制帧或低清放大掩盖成本。
- 已停止却仍渲染：stdin 的 Ctrl+C 不是所有后台进程的 SIGINT。用任务 STOP 文件或确认身份后的进程信号；只停止自己的资源。
- 缓存混乱：保留首个错误和指纹，检查同一任务的状态；不清空全部用户缓存、不重复新建实例。
- 浏览器拒绝本地文件：遵守宿主策略，不换地址或其它浏览器接口绕过。使用允许的导出帧和解码检查，并明确未做完整播放。

## 已验证与未验证

起源流程实际验证过：macOS ARM64、bpy 4.5.3、MPFB2 源码/CC0 系统资产、真实人体与服装权重、面部骨骼和表情修正、Metal/Cycles 与 EEVEE、原生帧渲染及 FFmpeg 编码。

起源流程没有证明：任何产品都无需美术判断、任何机器都能安装成功、所有版本兼容、基础模型等同 AAA 游戏最终角色、辅助骨骼等同布料物理仿真、局部帧通过等同整片已经人工播放验收。

脚本失败时先阅读当前版本的源码/官方文档，避免把旧样例参数当作事实。比如 MPFB 的个别示例曾把 gender 方向注释反，宏定义才是判断依据。

生产任务需要的适配写在任务目录，保留版本、证据和变更原因。修改 Skill 的主流程或脚本仍应单独遵守用户的 Skill 修改确认要求。
