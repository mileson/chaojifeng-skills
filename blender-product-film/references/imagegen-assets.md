# ImageGen、UV 和资产许可

## 自动选择正确的图像用途

输入已有品牌素材时优先使用原件。缺少的图像按用途生成：角色/场景美术参考、产品道具表面纹理、已定义 UV 的基色图集、背景的概念参考。整张角色立绘不能代替用户要求的三维角色。

调用内置 ImageGen，按串行单任务生成。需要编辑本地图片时先查看它，再以最小参考集提交。不要在工具输出中打印完整 base64，记录保存路径和用途即可。

项目素材必须复制到任务目录或其明确的资产缓存。不能仅依赖 Codex 默认生成目录或 OS 临时目录。记录提示词、生成方式、参考图用途、文件 SHA256。

## 纹理合同

生成前取得目标网格的 UV 布局、材质分区和图集边界。让图像在这些约束内工作；必要时先导出 UV 技术图作为参考。

基色提示词应明确：平面材质扫描、无物体轮廓、无烘焙阴影/高光、无文字、分区坐标和颜色。默认把 ImageGen 的结果当作基色候选，不自动称为完整 PBR 材质或真实法线/粗糙度图。

对成熟人体资产，保留其匹配的皮肤、眼睛纹理与拓扑。ImageGen 可用于服装花纹和设计方向；不能把一张漂亮的人像包到任意头部上就宣称人物复原。

在曲面、接缝和多角度下检查纹理。使用 `blender.helpers.uv_albedo` 前确保目标网格存在 UVMap。模型形状的问题回到模型修正，不用贴图掩盖。

透明图需要实际检查 alpha。它可用于发丝纹理、道具贴花等适合的用途；若用户明确选择角色 2.5D 精灵，要单独标注并更改验收要求，不冒充真实骨架三维角色。

## 授权资产清单

用 `scripts/prepare_assets.py` 处理以下结构：

```json
{"assets":[{"id":"human-core","url":"https://official-source.example/asset.zip","sha256":"由官方校验或已核验下载计算的64位摘要","license":"CC0-1.0","license_source":"具体许可页面或资产头部证据","license_verified":true,"extract":true}]}
```

示例 URL 是结构示例，不是下载地址。必须由 Agent 核对实际来源和许可后替换。软件代码许可证与生成模型/素材许可证分别记录。MakeHuman 核心资产许可不能替代所有社区服装的许可。

本地已有文件可以使用 local_path 替代 url，并提供 SHA256。签名 URL、账号、token 不写入可分享清单；必要时通过已授权连接器先下载到本地。

缓存按内容哈希隔离。下载与解压串行，检查空间、路径遍历和体积。不要把模型大包、node_modules、Python 环境、供应商源码或用户历史装进 Skill 分发包。

## ImageGen 提示词骨架

写明：用途 → 产品/人物不变量 → 风格与色彩 → 视角/构图 → UV 或图集约束 → 透明/不透明需求 → 禁止出现的内容。

示例：为已经划定的服装 UV 图集生成低对比度亚麻基色纹理；指定分区与品牌色，禁止人脸、衣服轮廓、文字、阴影和高光。生成后必须查看并进行实际曲面贴图检查。
